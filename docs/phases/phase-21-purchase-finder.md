# Phase 21 — 구매처 찾기 (Claude 웹 검색)

> **이 문서 사용법**: Claude Code에 이 파일 전체를 컨텍스트로 넘기고 "**Step N을 진행해달라**"고 한 Step씩 요청한다. **사람** Step(모델·한도 결정, 마이그레이션 적용, 함수 배포, 측정 실행·판정, 실기기 확인, OTA)은 에이전트가 대신하지 않는다. 에이전트는 Step마다 변경 요약을 보고하고 **승인을 받은 뒤 커밋**한다. 커밋 메시지에 Phase·Step 번호를 넣지 않는다.
>
> **브랜치**: 최신 `dev`(Phase 15 요청 제한 머지됨)에서 `feat/phase-21-purchase-finder`. worktree `../wish-shot-eval`에서 작업한다(`../wish-shot-sec`는 RLS 점검이 쓴다). 이 폴더의 정답셋 원문·결과(`samples/goldset/data`·`out`, git 제외)는 Step 3 측정에 쓰므로 지우지 않는다 — `git clean`을 쓰지 않는다. 마이그레이션 번호는 `0007`(`0006`은 RLS 점검 수정용으로 비워 둔다).
>
> **1차(시연용 최소판)를 먼저 만든다**: 등록 폼에서 링크가 자동으로 채워지는 것이 개발용 앱에서 동작하는 데까지 먼저 가고, 나머지는 같은 브랜치에서 이어 한다.
> - **하는 것**: Step 1(확인 — 완료), Step 2(함수 + 전용 한도 `0007`), Step 5(등록 폼 링크 자동 채움 + 저장 뒤 붙이기), `0007` 적용·Web Risk 키 등록·함수 배포(사람), 개발용 앱 확인(사람). Web Risk 키가 없으면 링크가 항상 비므로 시연 전에 등록한다.
> - **나중에 하는 것**: 상세 화면 '구매처 찾기'(판매처 목록에서 고르기)와 보정 제안(아래 '나중에 하는 것'), Step 3·4 측정, Step 6 방침·문서, Step 7 OTA.
> - **1차에서도 지키는 것**: 불변식 1(실제 URL만)·2(보내는 값 제한)·3(전용 한도)·4(확실할 때만 채움)·5(덮어쓰지 않음)·6(비밀 값). 함수는 운영 프로젝트에 배포되고 공개 키로 만든 익명 세션도 부를 수 있으므로 **한도 없이 배포하지 않는다** — `0007`을 먼저 적용한다.
> - **머지하지 않는다**: 1차는 이 브랜치에서 함수를 배포하고(지금 이 함수를 부르는 운영 앱은 없다) 개발용 앱 + 개발 서버로 확인한다. 운영 앱에는 아무것도 나가지 않으므로 불변식 7(고지 선행)은 OTA 전까지 지키면 된다. PR은 나머지 Step까지 끝낸 뒤 올린다.
> - **멈추는 조건**: 사람이 정한 마감까지 개발용 앱에서 링크가 채워지지 않으면 멈추고 보고한다.
>
> **배포**: `0007` 마이그레이션 + 새 Edge Function 배포 + 앱 JS 변경(OTA). 지금 계획에는 네이티브 변경이 없다. OTA는 runtime별로 나간다 — 1.0.1·1.0.2 사용자에게 각각 보낼지 Step 7에서 정한다.
>
> **네이티브 패키지**: 새 네이티브 패키지도 구현 선택지에 넣는다. 방법을 고를 때 이미 설치된 패키지·JS로 하는 방법과 새 네이티브 패키지를 비교해 보고하고, 사람이 고른다. 비교 항목은 재빌드 여부와 배포 경로 변화, Expo SDK 57·RN 0.86·New Architecture 호환 근거, 개인정보 매니페스트·방침 영향, 유지보수 상태(최근 릴리스·열린 이슈), 구현·검증 비용이다. 이 Phase는 OTA 계획이라, 네이티브를 넣으면 배포가 스토어 빌드·심사(`release/v<버전>`)로 바뀌고 앱 지문(fingerprint)이 달라져 이후 OTA는 새 빌드 사용자만 받는다. 승인 없이 추가하지 않고, 추가할 때는 `npx expo install`의 SDK 호환 버전을 쓰며 기존 패키지 버전은 올리지 않는다.
>
> **레인 경계**: `parse-screenshot-text/**`, `samples/**`(정확도 측정 중), `modules/**`는 건드리지 않는다. 입구 채널은 기기에서 OCR 원문으로 판별하고, 정제 함수의 입출력은 바꾸지 않는다.
>
> **근거 원칙**: Claude API 웹 검색 도구의 지원 모델·버전명·파라미터·가격·구조화 출력과의 호환은 **Anthropic 공식 문서로 확인한 뒤** 쓴다(CLAUDE.md 규칙 6).
>

## 목표 (Goal)

위시 담기(등록) 폼에서 사진 분석이 끝나면 Claude가 웹을 검색해 **그 상품의 판매 페이지**를 찾아 링크 칸에 자동으로 채운다. 지금은 사용자가 링크를 직접 붙여 넣거나 공유 시트로 받아야만 링크가 생긴다.

**캡처한 내용과 캡처한 곳이 링크로 바로 들어가게 하는 것**이 목표다. 먼저 캡처의 입구 채널(어디서 캡처했나)을 확인하고 그에 맞게 찾는다.
- 쇼핑몰에서 캡처했으면(주소 또는 몰 고유 문구로 확인) 그 몰의 같은 상품 페이지를 넣는다.
- 공식 홈페이지 등 주소가 보이는 사이트에서 캡처했으면 그 사이트의 같은 상품 페이지를 넣는다.
- 몰·사이트 흔적은 없지만 제품 정보를 알 수 있으면(릴스·SNS 등) 브랜드·제품명으로 **공식 홈페이지**의 같은 상품 페이지를 찾아, 확실할 때만 넣는다.
- 확실하지 않으면 비워 둔다(null). 틀린 링크보다 빈칸이 낫다.

## 확정된 결정

- **찾는 주체**: 앱 서버 함수(Edge Function)가 부르는 Claude API의 웹 검색 도구. 같은 상품인지 고르기도 Claude(Haiku 5.5)가 한다.
  - **검토 후 제외한 검색 출처(2026-11-09)**: 실기기 확인에서 Anthropic 웹 검색이 한국 소규모 쇼핑몰을 잘 찾지 못하고(6~9초) 네이버 웹 검색에는 나와 다른 출처를 검토했다.
    - 네이버 쇼핑 검색 API: 2026-07-31 종료(대체 API 없음).
    - NAVER API HUB 웹문서 검색: 약관 특약(검색 API) 1.1 "네이버 검색결과를 제공하기 위한 목적으로만", 1.2 가공 없이 노출, 1.3 "데이터를 AI에 입력"·데이터(가공·파생물 포함) 저장 금지(1.4 캐싱만 기기 24시간·서버 이력 21일), 일반조건 7.2③ 사용자에게 API 이용 대가 수령 금지 — 결과를 거르고 AI가 고른 링크를 계속 저장하는 이 기능과 맞지 않는다. '사용자가 고른 검색 결과 주소를 링크로 저장'이 허용되는지는 NAVER API HUB에 문의했다(결과는 결과 기록에).
    - Google Custom Search JSON API: 새 가입 불가, 2027-01-01 종료.
- **실행 시점**: 등록 폼에서 AI 정제가 끝난 뒤 자동으로 부른다. 검색어에 정제 결과의 제품명·브랜드가 필요하므로 정제와 병렬로 돌리지 않는다(OCR 원문을 검색 쪽에 보내지 않기 위해서이기도 하다). 폼은 기다리지 않고 링크 칸만 나중에 채운다.
- **입구 채널 확인 → 검색 범위**(기기에서 OCR 원문으로 판별, 위에서부터 먼저 맞는 것):
  1. **도메인이 보임**(사파리 주소창·앱 안 브라우저 상단·캡처에 찍힌 주소) → 그 도메인 안에서만 검색(`allowed_domains`) → 그 사이트의 같은 상품 페이지. 공식몰·쇼핑몰 구분 없이 넣는다. 그 도메인이 사전의 몰이면 그 몰의 검색 도메인을 쓴다. 포털·블로그·SNS처럼 판매처가 아닌 주소(네이버 본체·블로그, 인스타그램, 유튜브 등)는 판매처로 보지 않고 2로 넘어간다.
  2. **판매처 주소는 없지만 몰 이름·고유 문구가 보임**(몰 앱 캡처, 또는 SNS 캡션의 "에이블리에서 샀어요" — 아래 입구 채널 사전) → 그 몰의 검색 도메인 안에서만 검색 → 그 몰의 같은 상품 페이지. 포털·SNS 주소가 함께 보여도 몰 이름을 따른다. 상품명·브랜드 글자는 빼고 찾는다('지그재그 패턴 니트' 같은 상품명이 몰로 읽히지 않게). 여러 몰이 함께 보이면 판별하지 않고 3으로 간다.
  3. **몰·사이트 흔적 없음**(릴스·SNS·잡지 등) → 브랜드·제품명으로 검색하고 사전의 몰 도메인은 검색에서 뺀다(`blocked_domains`) → 브랜드 공식 홈페이지의 같은 상품 페이지일 때만 넣는다.
  - 못 찾았거나 확실하지 않으면 null. 쇼핑 검색 링크 같은 대체 링크도 넣지 않는다.
- **URL은 검색 결과에 실제로 나온 것만**: 모델이 쓴 URL도, OCR로 읽은 주소도 그대로 쓰지 않는다(오인식으로 깨진 링크 방지). 캡처의 주소는 검색 범위(도메인)로만 쓴다.
- **안전한 링크만**: https 주소만 받는다(기본 포트, IP 주소·아이디가 든 주소 제외). 먼저 알려진 악성 사이트 목록(Google Web Risk — 악성코드·피싱/사칭·원치 않는 소프트웨어)과 대조해 목록에 오른 주소는 버린다(키가 없거나 조회에 실패해도 버린다 — fail-closed. 이미 신고된 사이트만 잡는 한계가 있다). 그다음 함수가 고른 링크에 직접 접속해 인증서(만료·자체 서명·이름 불일치면 접속 실패), 리다이렉트(모두 https·같은 사이트 안), 응답 코드(정상 응답만 — 사전의 대형 몰은 봇 차단 응답도 허용)를 확인하고, 통과하지 못하면 비워 둔다.
- **덮어쓰지 않음**: 링크 칸이 이미 차 있으면(공유 시트로 받은 링크·사용자가 입력한 링크) 검색하지 않는다.
- **저장 뒤 붙이기**: 결과가 오기 전에 저장하면, 결과가 왔을 때 그 위시의 링크가 **비어 있을 때만** 붙이고 "링크를 찾아 붙였습니다. 확인해 주세요" 안내를 띄운다. 앱이 백그라운드로 가 결과를 놓치면 비워 둔다. 다른 필드(제품명·브랜드·가격 등)는 저장 뒤에 바꾸지 않는다 — 제품명·브랜드는 중복 판정에 쓰여 저장 뒤 바꾸면 다른 위시와 충돌할 수 있다.
- **한도**: 이 함수 전용 카운터(마이그레이션 `0007`, 사람이 SQL Editor로 적용). 정제 함수 카운터(`0005`)와 따로 센다. 한도에 걸리면 링크만 비워 둔다(오류 안내 없음).
- **가격은 다루지 않는다**: 폼의 가격은 캡처에서 뽑은 값 그대로다. 판매처 표시가는 가져오지 않는다.

## 하지 않는 것

- 신호가 없을 때의 검색: 이미지 분석 없는 수동 입력, 제품명이 없는 분석 결과, 링크 칸이 이미 찬 경우
- 정제와 링크 찾기의 병렬 실행
- 링크 외 필드의 저장 뒤 변경, 보정 자동 반영, 가격 덮어쓰기
- 가격 추적·알림, 제휴 링크
- 상품 이미지·OCR 원문 전송(제품명·브랜드·입구 채널만 보낸다)

## 나중에 하는 것 (1차 제외)

- **상세 화면 '구매처 찾기'**(2026-11-09: '몰로 바로 가기(통로)' 새 Phase 초안이 이 자리를 대신할 수 있다 — 그 Phase에서 정한다): 링크가 빈 위시를 위해 판매처 목록(공식 판매처 우선 + 주요 몰 2~3곳, 판매처 이름·'공식' 표시)을 보여 주고 사용자가 고르게 한다. 같은 함수를 목록 모드로 쓴다. 표시가는 근거(검색 인용)가 있을 때만 '검색 시점 표시가'로 보여 주고 '최저가'로 단정하지 않는다.
- **보정 제안**: 같은 상품 페이지의 제목에 근거해 제품명·브랜드를 제안하고, 사용자가 '적용'을 누를 때만 반영한다(`updateItem`, 다른 위시와 이름이 겹치면 `DuplicateItemError`로 막고 안내). 제안 글자가 근거 페이지 제목에 정규화 후 부분 문자열로 들어 있을 때만 제안한다(`normalizeName`과 같은 규칙). 가격은 보정하지 않는다. 제안 위치(등록 폼·상세)는 그때 정한다.

## 알려진 사실 (Step 1 — 2026-11-09 공식 문서로 확인)

- 웹 검색은 서버 도구라 `tools`에 선언하면 Anthropic이 검색을 실행한다. 검색 1회 $0.01(1,000회당 $10, 오류 난 검색은 무과금) + 토큰. 검색 결과는 입력 토큰으로 센다.
- 지원 모델: Haiku 4.5·Haiku 5.5·Sonnet 5.5·Opus 5.5 등. 버전은 기본 `web_search_20250305`를 쓴다(결과가 `web_search_result` 목록으로 바로 와 후보를 모으기 쉽다). 동적 필터링 버전(`web_search_20260209` 이후)은 Haiku 5.5 지원이 문서로 확정되지 않아 쓰지 않는다.
- 파라미터: `max_uses`(한 턴 검색 횟수 상한 — 넘으면 `max_uses_exceeded` 오류 결과), `allowed_domains`/`blocked_domains`(둘 중 하나만. 스킴 없는 도메인, 하위 도메인 자동 포함, 와일드카드는 경로에만, ASCII만 — 형식이 틀리면 400), `user_location`(`{ "type": "approximate", "country": "KR", "timezone": "Asia/Seoul" }` 등, `city`·`region`·`country`·`timezone` 중 하나 이상).
- 결과: `web_search_tool_result` 블록. 성공이면 `content`가 `web_search_result` 목록(`url`·`title`·`page_age`·`encrypted_content`), 결과가 없으면 빈 목록, 오류면 `content`가 객체(`{ "type": "web_search_tool_result_error", "error_code" }` — `too_many_requests`·`invalid_tool_input`·`max_uses_exceeded`·`query_too_long`·`request_too_large`·`unavailable`). HTTP는 200이다.
- 인용은 웹 검색에서 항상 켜져 있다(`web_search_result_location` — `url`·`title`·`cited_text` 최대 150자). 인용과 구조화 출력(`output_config.format`)을 함께 쓰면 400이다. 웹 검색과 구조화 출력을 한 요청에 쓰는 경우는 문서에 명시가 없다 → **2회 호출**(검색 → 고르기).
- 서버 측 반복이 길어지면 `stop_reason: "pause_turn"`이 온다. 받은 assistant 내용을 그대로 붙이고 같은 `tools`로 다시 보낸다(이어 보내기 횟수에 상한을 둔다).
- 모델별 단가(100만 토큰당 입력/출력): Haiku 5.5 $0.10/$0.50(프롬프트 10만 토큰 이하, 넘으면 $0.50/$2.50) · Haiku 4.5 $1/$5 · Sonnet 5.5 $2/$10 · Opus 5.5 $4/$20. Haiku 5.5는 토크나이저가 달라 같은 글이 토큰 약 30% 더 나오고, `temperature`는 기본값만 받는다(정제 함수처럼 0으로 고정할 수 없다).

## 설계

### Edge Function `find-purchase-links`(신규)
1. 사용자 JWT 확인(정제 함수와 같은 방식).
2. 입력: `{ productName, brand?, domain?, mall? }`(텍스트만, `domain`과 `mall`은 둘 중 하나만). 길이 상한·빈 값 검사. `domain`은 스킴·경로·포트·`www.`·`m.`을 떼어 호스트명만 남긴 뒤 형식 검사(ASCII, 점 포함, `co.kr`처럼 공용 접미사만 남는 이름·예약 이름 거부), `mall`은 사전의 몰 id만 — 어긋나면 400. 판매처가 아닌 플랫폼 도메인이면 채널이 없는 것으로 본다.
3. **요청 한도**: 전용 카운터(`0007`)로, 검증을 통과한 요청만 Anthropic을 부르기 전에 센다. 사용자 시간·하루(한국 시간 0시) + 전체 하루. 넘으면 429. 카운터를 쓸 수 없으면(오류·시간 초과) 거절한다(503 — 정제 함수와 달리 fail-closed. 웹 검색은 비용이 커서 한도 없이 돌지 않게 한다). 실패 기록은 정제 함수(`0005`)와 같은 방식이고, 실패 사유 목록은 이 함수용으로 따로 둔다.
4. **1차 호출 — 검색**: 웹 검색 도구(`web_search_20250305`, `max_uses` 2~3, `user_location` 한국). 검색 범위는 입구 채널대로 정한다 — 도메인이면 `allowed_domains: [도메인]`(사전의 몰이면 그 몰의 검색 도메인), 몰이면 `allowed_domains: 그 몰의 검색 도메인`으로 그 사이트 안에서 같은 상품 페이지를 찾게 한다. 채널이 없으면 `blocked_domains: 사전의 몰 도메인`(브랜드가 그 몰 자체이면 그 몰은 빼지 않는다 — 예: 이케아)으로 브랜드 공식 홈페이지를 찾게 한다. 응답의 `web_search_result`에서 **후보 URL 목록(번호·도메인·제목)** 을 서버가 직접 모은다(검색 범위 밖 도메인은 버린다).
5. **2차 호출 — 고르기(구조화 출력, 도구 없음)**: 후보 목록(번호·도메인·제목)과 제품명·브랜드만 주고 `{ index: number | null, isOfficial: boolean }`를 받는다. 묶음 수량·용량·사이즈·색상만 다른 페이지는 **같은 상품**으로 본다(링크를 타고 들어가 몰 안에서 옵션을 고르기 쉬우므로, 옵션이 정확히 같지 않아도 링크를 넣는 쪽을 택한다 — 2026-11-09 사람 결정). 같은 상품이 여럿이면 상품명의 색상·수량·사이즈와 맞는 것을 먼저 고른다. 같은 상품 페이지가 확실할 때만 번호를 주고, 아니면 null. 서버는 `index`가 후보 범위 안인지 확인하고 **URL은 후보 목록에서 꺼낸다**(카테고리 추천 화이트리스트와 같은 방식). 채널이 없는 경우엔 `isOfficial`이 true일 때만 돌려준다.
6. **링크 확인**: ① Google Web Risk Lookup API(`uris.search`, 위협 유형 `MALWARE`·`SOCIAL_ENGINEERING`·`UNWANTED_SOFTWARE`)로 대조한다 — 목록에 있거나 키 없음·조회 실패면 null. 키는 함수 시크릿 `WEB_RISK_API_KEY`에만 두고 `x-goog-api-key` 헤더로 보낸다. 악성일 수 있는 사이트에 접속하기 전에 한다. ② 고른 링크에 함수가 직접 접속한다(본문은 읽지 않음). 인증서 검증을 통과해야 하고, 리다이렉트는 최대 3단계까지 모두 https·같은 사이트 안이어야 하며, 최종 응답이 2xx여야 한다(사전의 대형 몰은 401·403·429도 허용). 통과하지 못하면 null. 돌려주는 주소는 검색 결과의 원래 주소다.
7. 출력: `{ link: { url, domain, kind } | null }`. 후보가 없거나 같은 상품이 확실하지 않거나 거절(refusal)이면 `{ link: null }`(200). 검색 도구 오류·`pause_turn` 이어 보내기 상한이 있어도 모은 후보가 있으면 고르기로 진행한다. 입력·인증·한도는 4xx, Anthropic 호출 실패는 5xx. 앱은 어떤 실패든 링크를 비워 둔다.
8. 로그: 채널 종류(도메인·몰·없음)·후보 수·채웠는지·검색 횟수·토큰·링크 확인 결과(종류만)만. 제품명·브랜드·도메인·URL은 남기지 않는다.

### 앱 (등록 폼)
- **입구 채널 판별(기기)**: OCR 원문에서 ① 도메인·URL 패턴(사파리 주소창, 앱 안 브라우저 상단, 캡처에 찍힌 주소 — `www.`·`m.` 같은 앞부분은 떼고 호스트명만), 없으면 ② 입구 채널 사전의 몰 고유 문구를 찾는다. 결과로 도메인 또는 몰 id 하나만 보내고 원문은 보내지 않는다. `src/lib/purchaseChannel.ts`에 순수 함수로 둔다.
  - 주소로 인정하는 것: 스킴·`www.`·경로가 붙은 주소, 또는 그 줄이 거의 주소뿐인 경우(주소창 줄 — 'AA'·'가가' 버튼 글자 정도만 함께). '팔로우'·'좋아요' 같은 SNS 표시가 있는 캡처에선 맨 도메인(계정명일 수 있음)을 인정하지 않는다.
  - 버리는 것: 이메일·계정명의 일부(앞 글자가 문자·숫자·밑줄·점·@), OCR이 끊어 읽은 주소('brand.co. kr'), 공용 접미사만 남은 이름·예약 이름(서버와 같은 목록), 서로 다른 사이트 주소가 여럿인 경우.
  - 판매처 주소가 없으면 몰 이름·고유 문구로 판별한다(포털·SNS 주소가 함께 보여도). 이때 정제 결과의 상품명·브랜드 글자는 빼고 찾는다.
- **실행**: AI 정제가 성공해 제품명이 있고 링크 칸이 비어 있을 때 부른다(`src/hooks/usePurchaseLinkSearch.ts`). 같은 (제품명·브랜드·채널)로는 한 번만 부르고(조합별로 결과를 보관), 다시 분석해 값이 바뀌면 그 조합의 결과만 쓴다. 진행 중엔 링크 칸에 '링크 찾는 중…'과 스피너를 표시하고, 찾으면 'AI가 채움'으로 채운다. 그사이 사용자가 링크를 입력하면 결과를 버린다. 사용자가 제품명·브랜드를 AI 값과 다른 제품으로 고치면(정규화 비교) AI 값으로 찾은 링크는 쓰지 않는다. 실패·한도·없음·앱 쪽 시간 제한(90초)은 조용히 빈칸으로 둔다. 저장이 시작되면 새 찾기를 시작하지 않는다.
- **저장 뒤 붙이기**: 결과가 오기 전에 저장하면 저장된 위시 id로 이어 받아, 링크가 아직 비어 있을 때만 저장한다(조건부 업데이트 `setSourceLinkIfEmpty`). 붙이면 "저장한 위시에 판매처 링크를 붙였습니다. 확인하세요." 안내(닫기·보기)를 띄운다. 화면이 닫혀도 끝까지 받도록 진행 중인 작업은 화면 상태 밖에서 이어 간다. 저장 뒤 3분이 지나 도착한 결과는 붙이지 않는다(다른 화면에서 뒤늦게 안내가 뜨지 않게). 저장 중에는 링크 칸을 잠근다.
- **덮어쓰기 저장(중복)**: 기존 위시에 링크가 있고 링크 칸을 손대지 않았으면 기존 링크를 그대로 둔다(불변식 5 — 찾은 링크로 바꾸지 않음).
- 호출은 `src/lib/queries/`에 새 함수로(규칙 11). 문구는 규칙 4.

## 불변식 (Invariants)

1. **실제 URL만, 안전한 링크만**: 링크 칸에 들어가는 URL은 서버가 검색 결과에서 꺼내고 악성 사이트 목록 대조(Google Web Risk)와 접속 확인(https·인증서·리다이렉트·응답 코드)을 통과한 것뿐이다. 캡처의 주소는 검색 범위로만 쓴다.
2. **보내는 값 제한**: 제품명·브랜드·입구 채널(캡처에 보인 도메인 또는 몰 id)만 보낸다. 이미지·OCR 원문·메모·다른 위시 정보는 보내지 않는다.
3. **조건부 자동 실행·한도**: 분석된 제품명이 있고 링크 칸이 비어 있을 때만 자동으로 부르고, 이 함수 전용 한도를 둔다.
4. **확실할 때만 채움**: 채널이 있으면 그 사이트의 같은 상품 페이지, 채널을 알 수 없으면 공식 홈페이지의 같은 상품 페이지일 때만 채우고, 아니면 null. 대체 링크를 넣지 않는다.
5. **덮어쓰지 않음**: 이미 있는 링크(공유 시트·사용자 입력·저장 뒤 편집)는 바꾸지 않는다. 저장 뒤에는 링크만, 비어 있을 때만 붙인다.
6. **비밀 값**: Claude 키는 함수 시크릿에만.
7. **고지 선행**: 방침과 앱 안내에 "등록할 때 제품명·브랜드·캡처에서 알아낸 판매처(사이트 주소·몰)가 링크 찾기(Anthropic 웹 검색)에 전송되고, 찾은 링크 주소는 악성 사이트 확인(Google Web Risk)에 전송된다"를 넣고 공개한 뒤 OTA를 낸다.
8. **문서 정합(규칙 8)**.
