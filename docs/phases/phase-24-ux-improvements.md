## 목표 (Goal)

- **A. 탭**: 자주 쓰는 '전체'를 앱을 열면 바로 보이게 하고, 탭 순서를 정리한다. 공유 시트 처리를 탭 화면에서 떼어 앱 전체에서 한다.
- **B. 등록·편집 폼**: 필수 입력처럼 보이는 부담을 줄이고, 긴 값을 한 줄로 깔끔하게 보인다.
- **C. 알림**: 저장 뒤 링크가 붙는 등 '사용자가 보지 못한 변화'를 흐름을 끊지 않고 알린다 — 3초 스낵바([보기]로 이동), '알림' 탭에 기록, 아직 열어 보지 않은 위시 타일에 와인색 점.

## 확정된 결정 (2026-11-09 사람)

- **탭 순서**: 카테고리 · 전체 · 알림 · 검색. **앱을 열면 전체 탭**. 알림 탭은 검색 앞.
- **AI 칩 삭제**: 등록 폼의 'AI가 채움' 칩을 없앤다. "AI가 채웠습니다. 확인하세요." 같은 확인 안내 문구는 남긴다.
- **한 줄 입력**: 폼 입력 칸에서 값이 두 줄로 보이지 않게 한다(예: 편집 화면 링크가 두 줄로 보임). 넘치는 글자는 한 줄로 이어 쓰고, 오른쪽 끝 그림자(페이드)로 글자가 이어져 있음을 표시한다.
- **링크 칸 이동·안내**: 링크 칸을 카테고리 밑으로 옮겨 필수 입력 묶음(제품명·브랜드·가격)에서 뺀다. '링크 찾는 중' 표시 외에, 저장한 뒤에 찾아도 링크를 붙인다는 안내를 더한다.
- **검색 결과 링크 안내 삭제**: 상품 페이지 대신 몰·사이트 검색 결과로 연결한 링크도 사용자에게는 '연결된 링크'다. "상품 페이지를 찾지 못해 … 검색 결과로 연결합니다" 같은 구분 안내는 과도한 정보라 없앤다. 알림 문구도 링크 종류를 나누지 않는다.
- **공유 시트 처리 분리**: 공유로 받은 이미지·URL 처리는 배경이 되는 탭과 관계가 없다. 지금은 예전 로그인 벽 시절 구조가 남아 카테고리 홈 화면이 처리하고 있다(그 화면이 보일 때만 동작). 이를 화면에서 떼어 앱 전체(루트)에서 처리해, 기본 탭이 무엇이든 동작하게 한다.
- **타일 표시(링크 찾기 상태)**: 새로 담긴 위시라도 저장 뒤 링크를 찾지 않으면 아무 표시도 하지 않는다.
  - **찾는 중**(저장 뒤 이어 찾기): 타일을 약간 흐리게 — 아직 진행 중이라는 느낌만 준다(썸네일 로딩처럼 보이게 하지는 않는다). 점은 찍지 않는다.
  - **찾음**(링크가 붙음): 흐림을 지우고 좌상단 와인색 점. 상세를 열면 점을 지운다. 점에 흰 외곽선은 두지 않는다(점이 몇 장에만 찍히므로).
  - **못 찾음**: 흐림만 지운다 — 평소 타일로 돌아가는 것이 '저장이 끝났다'는 표시다.
- **못 찾은 위시의 링크 안내**: 상세 화면 링크 버튼은 링크가 없으면 비활성(지금 동작 그대로 — `item/[id]/index.tsx`). 링크 칸 자리표시 "링크를 직접 입력하세요" — 등록 폼은 '링크 찾는 중…' 뒤 못 찾았을 때(그 밖 `https://`), 편집 화면은 빈 링크 칸이면 항상(편집은 링크를 자동으로 찾지 않아 빈 칸이면 어차피 직접 입력 — 2026-11-09 사람 결정, 처음엔 '못 찾은 위시'를 기기에 14일 기록해 그 위시에만 보이려 했으나 기록 없이 단순하게)(사람 예시 "링크를 직접 저장해주세요"를 서비스 톤으로 — 칸은 입력하는 곳이고 저장은 [저장] 버튼이므로 '입력', 대화체 '~해주세요' 대신 기존 문구 "직접 입력하세요"와 같은 '~하세요').
- **작성 중에 새 공유가 오면 묻는다**: 등록·편집 폼이 떠 있을 때 새 공유가 오면 앱 자체 확인창으로 묻는다 — [지금 열기](작성 중인 내용 버림) / [저장 후 열기](새 공유를 맡아 두고, 지금 폼을 저장하거나 취소해 닫으면 이어서 연다 — 실무의 '대기열' 방식, 아무것도 잃지 않고 화면도 쌓이지 않음). 처음엔 iOS 기본 확인창([계속 작성]이면 새 공유 버림)으로 했으나, 실기기에서 묻는 중에 또 공유하면 처음 창이 그대로 남아(기본 확인창은 띄운 뒤 내용을 바꾸거나 닫을 수 없음) 2026-11-09 사람이 바꿨다. 시트 쌓기는 저장 뒤 카테고리 화면 이동과 충돌하고 뒤에 남은 폼을 잊기 쉬워 택하지 않았다. (Phase 7에서는 폼을 조용히 닫고 새 공유를 열기로 했었다 — JS만으로는 폼을 지킬 수 없다고 봤기 때문인데, 아래 '알려진 사실' 1로 가능해졌다.)
- **온보딩 카테고리 안내**: 탭 바의 '카테고리' 버튼을 비춘다(카드 3장 → 카테고리 안내 → 등록 폼 투어 순서는 그대로).
- **편집 화면**: 등록 폼과 같은 순서(링크를 카테고리 밑으로)와 한 줄 입력을 모두 적용한다.
- **계측**: 이벤트 2개를 더한다 — `link_attached`, `notification_opened`(아래 설계 C).
- **알림 보관**: 최근 **20개·14일**까지. 보관에서 빠진 알림은 타일 점도 함께 사라진다.
- **알림 종류**: 저장 항목에 `type`(지금은 `'link_attached'` 하나)만 두고, 문구는 한 곳에서 정한다. 새 종류는 필요할 때 type·문구만 더한다.

## 하지 않는 것

- 푸시 알림(앱 밖 알림) — 결과는 앱이 켜져 있을 때만 붙는다.
- 서버 저장 — 알림·안 본 표시는 기기 안에만 둔다(익명 계정, 링크 붙이기 자체가 앱 안에서 일어남).
- 새로 담긴 위시의 New 점(위 결정)
- 링크 찾기 로직(Edge Function `find-purchase-links`·입구 채널 판별) 변경 — Phase 21 후속에서 한다.
- 다크 모드 적용 — 앱은 라이트 전용이다(`colorsDark`는 상세 뷰어만 쓴다). 새 화면·컴포넌트도 `colors`(라이트)를 쓴다.

## 알려진 사실 (Step 1 — 2026-11-09 코드로 확인)

1. **공유 딥링크와 화면 이동** — expo-router 57.0.19 `build/link/linking.js`의 `subscribe`는 앱이 켜져 있을 때 들어온 링크를 `redirectSystemPath({ initial: false })`에 넘기고, 결과가 비면(`null`) **화면을 이동하지 않는다**(`if (href) listener(href)`). 첫 실행 링크는 `getLinkingConfig`의 `getInitialURL`에서 `initial: true`로 넘어온다. 반환 타입은 `string | null`. → 앱이 켜져 있을 때 온 공유는 딥링크로 이동하지 않게 하고, 공유 처리기가 이동을 혼자 맡을 수 있다(딥링크 이동과 공유 데이터 도착이 경쟁하지 않는다).
2. **expo-share-intent 8.0.1** — `resetShareIntent()`는 네이티브 저장소까지 지우고, 값이 있었을 때만 `onResetShareIntent`를 부른다. 지금 `_layout.tsx`의 `onResetShareIntent: () => router.replace('/')`는 공유를 처리할 때마다 숨은 `replace('/')`를 일으킨다. `resetOnBackground: true`는 처리하지 않은 공유를 백그라운드로 갈 때 지운다. 앱이 다시 활성화되면 마지막 링크로 네이티브 값을 다시 읽으므로, 처리한 공유는 반드시 `resetShareIntent()`로 지워야 같은 공유가 다시 오지 않는다.
3. **지금 공유 처리 위치** — `(tabs)/index.tsx`(카테고리 홈)가 `useIsFocused` + ref 잠금으로 처리하고, URL은 `router.push('/all', { attachLink })`, 이미지는 `router.push('/register', { imageUri, imageMime })`. 홈이 포커스가 아니면(위에 다른 화면) 기다린다. `share_intent_received` 계측도 여기서 한다.
4. **온보딩** — 카테고리 안내 대상(`home.addCategory`)은 카테고리 홈의 '+ | ···' 알약에만 있다. 탭 화면은 처음 열 때 마운트되므로 기본 탭이 전체면 측정에 실패하고, 지금 코드는 카테고리 안내를 조용히 건너뛰어 바로 등록 폼 투어로 간다. `OnboardingGate`는 공유로 열렸는지를 `hasShareIntent`로 판단하는데, 공유 데이터는 비동기로 늦게 오므로 공유로 열어도 온보딩이 뜰 수 있다(경쟁).
5. **라우트 사용처** — `/all`로 가는 곳은 공유 처리 1곳. `router.replace('/')`는 6곳: `login.tsx`(로그인 후), `register.tsx`(온보딩 투어 종료 대체 경로), `settings.tsx`(개발용 세션 리셋), `category/[id].tsx`(삭제된 카테고리 리다이렉트), `item/[id]/edit.tsx`·`item/[id]/index.tsx`(홈 복귀 대체 경로).
6. **폼** — 'AI가 채움' 칩은 `FormRow`의 `ai` prop이고 등록 화면만 쓴다. `DisclosureRow`의 `aiLabel`은 쓰는 곳이 없다. **편집 화면 링크가 두 줄로 보이는 원인은 코드에서 찾지 못했다** — 등록·편집의 링크 입력은 모두 단일 줄 `TextInput`(iOS UITextField)이라 줄을 바꿀 수 없는 구조다. 재현 화면(스크린샷)을 받아 Step 3에서 확정한다.
7. **스낵바 자리** — 루트 레이아웃에 그린 뷰는 네이티브 모달(등록·편집 `modal`, 상세 `fullScreenModal`, 정보 `formSheet`) 아래에 깔린다(Phase 7 코치마크가 겪은 문제와 같다). `react-native-screens`의 `FullWindowOverlay`는 별도 창에 그려 모든 화면 위에 보이고, 자식 밖의 터치는 아래로 넘긴다. 직접 의존성이라 네이티브 코드가 이미 빌드에 들어 있다.
8. **설정 진입** — 설정 톱니는 카테고리 홈 헤더에만 있다. 전체를 첫 화면으로 하면 설정이 한 탭 떨어진다.
9. **탭 바 폭** — 탭당 좌우 여백 24pt 기준으로 4탭이면 약 324pt(지금 3탭 약 252pt). 375pt 폭에는 들어가지만 확대 보기(320pt)나 큰 글자에서는 넘친다.

## 설계 (Step 1 확정)

### A. 탭·공유 처리

- **라우트 이름 변경**(`git mv`로 기록 유지): `(tabs)/index.tsx` = **전체**(기존 `all.tsx`) → `/`가 전체가 되어 앱을 열면 전체 탭. `(tabs)/categories.tsx` = **카테고리**(기존 `index.tsx`). `(tabs)/notifications.tsx` = **알림**(신규). `(tabs)/search.tsx` 그대로.
  - `replace('/')` 6곳은 전체로 가도 된다. **삭제된 카테고리 리다이렉트만 `/categories`**로 보낸다(카테고리를 보던 흐름).
  - 상세의 좌우 넘김 컨텍스트 `ctx: 'all'`은 그대로 둔다(라우트 이름과 무관).
- **탭 바**(`CustomTabBar`): 순서 카테고리 · 전체 · 알림(`bell`) · 검색. 4탭이 320pt 폭(확대 보기)에도 들어가도록 탭 좌우 여백을 24pt → 16pt로 줄이고(알약 약 260pt — 3탭 때 약 252pt), 라벨 글자 확대는 1.3배까지. 알림 탭에 안 읽은 개수 배지(와인색 원·흰 숫자, 아이콘 우상단). 접근성 라벨 "알림, 읽지 않은 알림 N개".
- **설정 톱니**: 전체 헤더에도 둔다(카테고리 헤더의 것은 유지).
- **공유 처리기**(신규 컴포넌트, `_layout.tsx`의 `AuthGate` 준비 분기에서 `Stack` 옆에 1개 — `OnboardingGate`와 같은 자리):
  - 익명 세션 준비 뒤에만 그려진다(그 분기 자체가 세션 준비 뒤). 이동 전에 네비게이터 준비(`navigationRef.isReady()`)를 확인하고, 아니면 다음 프레임에 다시 본다.
  - **중복 방지**: ref 잠금(처리 시작 시 잠그고 `hasShareIntent`가 내려가면 푼다) + 처리 직후 `resetShareIntent()`(네이티브 값까지 지움). `_layout.tsx`의 `onResetShareIntent`(숨은 `replace('/')`)는 없앤다. expo-share-intent가 네이티브 값을 두 곳(링크 변경·앱 활성화)에서 읽어 같은 공유가 잠금이 풀린 뒤 한 번 더 올 수 있으므로, 같은 공유(종류 + URL 또는 파일 경로)가 3초 안에 다시 오면 버린다.
  - **이미지** → 위에 뜬 화면을 모두 닫고(`dismissAll`) 등록 폼을 연다. 전체 탭이 링크 저장 모드면 그 모드를 끈다(배경 탭은 그대로).
  - **URL**(webUrl 또는 text 안의 첫 URL) → 위에 뜬 화면을 닫고 전체 탭 링크 저장 모드로 간다. 이미 모드 중이면 새 URL로 바꾼다.
  - **등록·편집 폼이 떠 있으면**(`/register`, `/item/[id]/edit`) 앱 자체 확인창(`ShareConfirmDialog` — `FullWindowOverlay`, iOS 확인창 모양 270pt)으로 묻는다 — 제목 "새 사진을 받았습니다"/"새 링크를 받았습니다", 본문 "지금 열면 작성 중인 내용은 저장되지 않습니다.", [저장 후 열기] · [지금 열기]. 묻는 중에 공유가 또 오면 확인창 내용이 마지막 공유로 바뀐다. ### B. 등록·편집 폼

- **AI 칩 삭제**: `FormRow`의 `ai` prop·`aiBadge` 스타일과 쓰지 않는 `DisclosureRow`의 `aiLabel`을 지운다. 분석 상태 문구("AI가 채웠습니다. 확인하세요." 등)와 카테고리 추천 안내("AI가 추천한 카테고리입니다. 바꾸려면 눌러 선택하세요.")는 남긴다. `autofill_edited` 계측에 쓰는 '자동으로 채운 값' 판정은 그대로 둔다.
- **한 줄 입력 컴포넌트**(`FormField.tsx`에 추가, 등록·편집 공용 — 제품명·브랜드·가격·링크):
  - 넘치지 않으면 지금처럼 오른쪽 정렬.
  - 넘치면(포커스 밖) 왼쪽 정렬로 앞부분을 보이고 오른쪽 끝에 `LinearGradient` 페이드(카드 배경색으로 사라짐). 넘침 판정은 같은 글꼴의 숨은 한 줄 텍스트 폭과 칸 폭을 비교한다.
  - 포커스 중에는 기본 입력 동작(커서 위치로 스크롤), 페이드는 숨긴다.
  - 입력하지 않고도 옆으로 밀어 잘린 부분을 볼 수 있다(덮개를 가로 스크롤로 — 민 만큼 왼쪽 끝도 흐리고, 끝까지 밀면 오른쪽 흐림은 사라짐, 탭하면 입력 시작). 실기기 확인 뒤 2026-11-09 사람 요청.
  - 페이드 끝 색은 `theme.ts`에 투명 토큰(카드 배경 0% — 예: `bgCardClear`)을 새로 둔다(원시 hex 금지, `transparent`는 iOS에서 회색 띠가 생길 수 있음).
- **순서**: 카드 1 = 제품명·브랜드·가격 → (카테고리 추천 안내) → 카드 2 = 카테고리·링크 → (링크 안내) → 카드 3 = 메모 → 태그. 편집 화면도 같은 순서(편집은 링크 찾기가 없어 '찾는 중'·링크 안내 없음).
- **링크 칸**: '링크 찾는 중…' 자리표시와 스피너는 그대로. 검색 결과 링크 안내(`linkHint`)와 `mallLabel` 사용을 지운다.
- **링크 안내 문구(최종 — 2026-11-10)**: 카드 2(카테고리·링크) 바로 아래 **오른쪽에 늘 보인다** — "저장 후에도 링크를 계속 찾습니다. 앱을 닫으면 중단됩니다." 찾는 동안만 보이게 했더니 요청 한도(계정 시간당 10·하루 30)에 걸려 바로 끝날 때 문구가 깜빡여, 사용자가 무엇인지 몰라 여러 번 다시 시도할 수 있다는 사람 판단으로 고정했다. 문구는 실무 원칙(진행 중인 동작을 담백하게 · 한 문장에 한 메시지·한 줄 · 관련 요소 가까이 — Siemens iX 진행 안내, 디지털 인사이트 모바일 UX 라이팅, Apple HIG Loading)과 국내 앱에서 흔한 '무엇이 계속되는지 + 무엇을 하면 멈추는지'(예: "앱을 종료하면 업로드가 중단됩니다") 형태를 따랐다 — 찾는 중이든 아니든 늘 맞는 문장이고, 지시("켜 두세요") 대신 결과("닫으면 중단")를 알린다. 편집 화면은 자동 찾기가 없어 넣지 않는다. 이전 문구: "지금 저장해도 링크를 계속 찾습니다. 앱은 켜 두세요." 실무에서 흔히 쓰는 '저장해도 계속 진행 → 앱 유지' 구조를 서비스 톤(규칙 4)으로 간결하게 옮겼다. 실제 동작과 맞는지: 앱 쪽 찾기 시간 상한이 90초라 앱을 켜 두면 결과는 저장 뒤 3분(`ATTACH_WINDOW_MS`) 안에 오므로 '3분'은 따로 적지 않는다. ### C. 알림

- **저장소**(기기, `src/lib/notifications.ts` — 화면 밖에서도 쓰는 작은 모듈 + 구독 훅):
  - AsyncStorage 키 `wishshot.notifications`. 항목 `{ id, type: 'link_attached', itemId, productName, createdAt, read }`. 앱 시작 뒤 처음 쓸 때 한 번 읽어 메모리에 둔다.
  - 보관: **최근 20개·14일**. 읽을 때와 쓸 때 정리한다.
  - **저장소는 하나**: 탭 배지는 '안 읽은 알림' 수, 타일 점은 '안 읽은 알림의 위시'로 계산한다(초안의 `wishshot.unseenItems`는 따로 두지 않는다 — 두 값이 어긋나지 않게).
  - **찾는 중**(타일 흐림): 같은 모듈이 메모리에만 '저장 뒤 링크를 찾는 중인 위시 id'를 둔다. `attachLinkAfterSave`가 시작할 때 넣고 끝날 때 뺀다. 찾기는 앱이 켜져 있는 동안만 이어지므로 기기에 저장하지 않는다(앱을 다시 켜면 사라진다). 배지에는 세지 않는다.
  - **찾기가 끝났을 때**: 붙임 → 알림 추가(점·배지·스낵바) 뒤 흐림 해제(빈틈 없이 흐림 → 점). 못 찾음(결과 없음·실패·한도·시간 초과, 3분이 지나 도착)·그사이 링크가 이미 들어감 → 흐림만 해제(기록 없음).
  - **읽음**: 상세 뷰어에서 그 위시가 화면에 나오면(좌우로 넘겨 볼 때 포함) 그 위시의 알림을 읽음으로. 알림 목록에서 눌러 상세로 갈 때도 같은 경로.
  - **삭제**: 위시를 지우는 두 곳(상세 삭제, 다중 선택 일괄 삭제)에서 그 위시의 알림을 지운다. 알림 목록을 열 때 이미 없는 위시의 알림도 정리한다.
- **스낵바**(앱 전체 1개 — `_layout.tsx`에서 `FullWindowOverlay` 안에 그림, 화면 밖에서 부르는 `showSnackbar` API):
  - 탭 바 바로 위(안전 영역 포함, 전체 탭 + 버튼과 같은 높이 — 3초 동안 + 버튼을 가릴 수 있다). 어두운 바탕(`colorsDark.bgCard`)·흰 글자.
  - 문구는 알림 목록과 같은 한 줄 "**{제품명}**에 링크를 붙였습니다"(`showSnackbar({ lead, text })` — `lead`만 굵게·말줄임) + [보기].

### 실기기 확인 목록 (Step 5 — Step 2~4가 끝날 때마다 해당 항목을 먼저 볼 수 있다)

- 앱을 열면 전체 탭. 탭 순서 카테고리 · 전체 · 알림 · 검색, 4탭 폭·라벨 잘림 없음(작은 기기 포함). 전체 헤더 톱니 → 설정.
- 공유 시트 — 앱이 꺼진 상태 / 켜진 상태 / 백그라운드에서 복귀, 각각 사진·URL: 사진 → 등록 폼, URL → 전체 탭 링크 저장 모드. 같은 공유가 두 번 열리지 않음. 카테고리·검색·알림 탭이나 상세·설정을 보던 중에도 동작.
- 등록·편집 폼 작성 중 새 공유 → 확인창 "새 사진(링크)을 받았습니다" [지금 열기](새 공유 화면) / [저장 후 열기](폼 유지 → 저장하거나 취소하면 새 공유가 이어서 열림). 묻는 중에 또 공유하면 확인창 제목이 마지막 공유로 바뀜(창이 겹치지 않음). 확인창이 등록·편집 모달 위에 보이고 버튼이 눌리는지.
- 앱을 끄지 않고 공유를 번갈아: 사진 → URL → 사진(앱이 멈추거나 꺼지지 않는지 — expo-share-intent가 이전 링크로 새 값을 읽을 때의 네이티브 처리 확인), 상세 뷰어 + 정보 시트가 떠 있을 때 공유(모달이 닫히고 새 화면이 뜨는지), 온보딩 중 공유.
- 링크 저장 모드 중 사진 공유 → 모드가 꺼지고 등록 폼. 모드 중 다른 URL 공유 → 새 URL로 바뀜.
- 첫 실행 온보딩(설정 '온보딩 다시 보기' 후 재실행): 카드 3장 → 탭 바 카테고리 버튼 안내(구멍 위치) → 등록 폼 투어 → 끝나면 전체 탭. 공유로 처음 열면 온보딩이 뜨지 않고 다음 일반 실행에 뜸.
- 등록·편집 폼: 칩 없음, 안내 문구 남음, 긴 제품명·링크가 한 줄 + 오른쪽 페이드(포커스 중엔 페이드 없음), 짧은 값은 오른쪽 정렬, 링크 칸이 카테고리 밑, 링크 찾는 중 안내 문구, 검색 결과 링크 안내 없음, 키보드 가림 없음.
- 링크를 찾는 중에 저장: 저장 직후 카테고리 화면 타일이 약간 흐림(점 없음) → 링크가 붙으면 흐림이 사라지고 와인색 점 / 못 찾으면 흐림만 사라짐. 링크를 찾지 않은 위시·직접 링크를 넣은 위시는 표시 없음.
- 못 찾은 경우: 등록 폼 링크 칸이 '링크 찾는 중…' 뒤 "링크를 직접 입력하세요"로 바뀜. 링크 없는 위시는 상세 링크 버튼 비활성, 편집 화면 빈 링크 칸 자리표시는 늘 "링크를 직접 입력하세요".
- 저장 뒤 링크가 붙을 때: 스낵바(3초·[보기]로 상세)가 카테고리 화면·상세 뷰어·정보 시트·새 등록 폼 위에서도 보임, 아래 화면 터치가 막히지 않음, 알림 탭 배지 숫자, 타일 점, 상세를 열면(좌우 넘김 포함) 점·배지가 사라짐, 위시를 지우면 알림도 사라짐.
- 모션 줄이기 켜고 스낵바, VoiceOver로 스낵바 안내·알림 탭 배지 읽기.
- 다크 모드에서도 라이트 화면 그대로(앱은 라이트 전용).
