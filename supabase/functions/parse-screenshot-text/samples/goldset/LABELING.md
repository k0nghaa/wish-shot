# 정답셋 라벨 규칙 (LABELING)

가격 자동채움 정확도를 재기 위한 **정답(라벨) 규칙**입니다. 측정을 시작한 뒤에는 이 규칙과 라벨을 고치지 않습니다. 고쳐야 할 일이 생기면 다음 버전 세트로 따로 만듭니다.

- 실행기: `samples/goldset-eval.ts` — 이 문서의 열 정의대로 `labels.csv`를 읽고 판정합니다.
- 원문 파일(`goldset/data/`)과 측정 결과(`goldset/out/`)는 **git에 올리지 않습니다**(`.gitignore`). OCR 원문에 타인의 계정명·댓글이 섞일 수 있고 레포가 공개돼 있기 때문입니다. 원문은 채팅·이슈·커밋 메시지에도 옮기지 않습니다.

## 0. 라벨링 전에

- **모델 출력을 보지 않고 라벨을 붙입니다.** `goldset/data/prod_parsed.csv`(운영 함수 출력)는 라벨이 끝날 때까지 열지 않습니다. 앱의 `goldset` 폴더 상세 화면에도 AI가 채운 값이 보이므로 열지 않습니다.
- 정답은 **화면에 실제로 보이는 값**입니다. OCR이 숫자를 잘못 읽었어도 정답은 화면의 값입니다. OCR 단계 실패는 실행기가 따로 셉니다('OCR 포함' 지표).
- `raw.csv`만으로 판단이 안 되면 본인이 찍은 캡처 원본(사진 앱)을 봅니다. `raw.csv`의 행 순서는 앱에 담은 순서(`created_at` 오름차순)와 같습니다.
- 대상은 **본인 계정으로 담은 기록만**입니다(`ops.internal_users`).

## 1. 파일과 열

`goldset/data/raw.csv` — 라벨링 입력(Step 3에서 만듦)

| 열 | 내용 |
|---|---|
| `id` | `analysis_logs.id` |
| `raw_text` | OCR 원문. 앱이 Edge Function에 보낸 텍스트와 같습니다(자르기·정규화 없음). 고치지 않습니다 |

`goldset/data/labels.csv` — 라벨러가 채우는 파일. 첫 줄은 아래 헤더를 그대로 씁니다.

```
id,type,item_category,price_gold,price_list,price_sale,name_keywords,brand_aliases,holdout,note
```

| 열 | 필수 | 형식 | 설명 |
|---|---|---|---|
| `id` | ✔ | `raw.csv`의 id | 모든 행에 라벨이 하나씩 있어야 합니다(빠짐·중복 금지) |
| `type` | ✔ | `A`~`F` | 화면 유형(2절). 여러 개에 해당하면 우선순위가 높은 쪽 |
| `item_category` | ✔ | `생활용품` / `가구·인테리어` / `패션` / `뷰티` / `전자` / `기타` | 주 상품의 품목(2절 '품목'). 판정에는 쓰지 않고 결과를 품목별로 나눠 보는 데만 씁니다. 가운뎃점·슬래시·공백 차이는 같은 값으로 받습니다(`가구/인테리어`도 됨) |
| `price_gold` | ✔ | 정수(원) 또는 `null` | **정답 가격.** 숫자만 씁니다(`42700` — 콤마·`원`·공백 없음). 정답이 없으면 글자 그대로 `null`. **빈칸은 '아직 라벨 안 함'으로 보고 실행기가 거부합니다** |
| `price_list` | | 정수 또는 빈칸 | 정가(할인 전 가격)가 화면에 있으면 그 값. 없으면 빈칸 |
| `price_sale` | | 정수 또는 빈칸 | 할인가가 화면에 있으면 그 값. 없으면 빈칸 |
| `name_keywords` | | `핵심어|핵심어` | 제품명 핵심어 1~2개. 빈칸이면 그 행은 제품명 지표에서 빠집니다 |
| `brand_aliases` | | `별칭|별칭` | 브랜드 한·영 별칭(예: `이솝|Aesop`). 빈칸이면 브랜드 지표에서 빠집니다 |
| `holdout` | | `1` / `0` / 빈칸 | 홀드아웃 여부. **라벨러가 채우지 않습니다** — Step 4에서 시드 고정 스크립트가 25%를 지정합니다 |
| `note` | | 자유 | 애매한 행의 사유. 원문을 옮겨 적지 않습니다 |

- 셀에 콤마나 줄바꿈이 들어가면 큰따옴표로 감쌉니다(엑셀·구글 시트에서 CSV로 저장하면 자동 처리).
- **UTF-8로 저장합니다.** 엑셀은 기본 'CSV'로 저장하면 한글이 CP949로 저장돼 깨집니다. 반드시 **'CSV UTF-8(쉼표로 분리)'** 을 고릅니다(구글 시트 내려받기는 UTF-8). 깨진 글자가 있으면 실행기가 멈추고 알려 줍니다.
- `raw.csv`는 내보낸 그대로 둡니다. 원문에 CR(`\r`)이 섞여 있으면 실행기가 멈춥니다. 앱 원문엔 CR이 없으므로, 내보내기에서 생긴 것인지 확인한 뒤 `--crlf-to-lf`로 실행합니다.
- `price_list`·`price_sale`는 정가 우선 정책 자체를 나중에 다시 판단하기 위한 보조 칸입니다. 측정 지표는 `price_gold`로만 계산합니다.

## 2. 화면 유형(type)

| 유형 | 내용 | 정답 예 |
|---|---|---|
| A | 정가·할인가 병기(커머스 상세) | 정가 |
| B | 할인가만 + 쿠폰·적립·배송비 노이즈 | 그 가격 |
| C | SNS 게시물 — 좋아요·조회·댓글 수만, 가격 없음 | `null` |
| D | 상세 + 추천·목록 상품 가격이 섞임 | 주 상품 가격 또는 `null` |
| E | 외화 가격만(해외 몰) | `null` |
| F | 텍스트가 거의 없는 이미지 중심 화면 | `null`('OCR 부족' 판정만 기록) |

- **여러 유형에 해당하면 F > E > C > D > A > B 순으로 하나만** 고릅니다(측정이 더 까다로운 특징을 우선).
- 실행기는 앱과 같은 기준으로 **원문이 20자 미만인 행은 호출하지 않고 'OCR 부족'으로만 셉니다**(`useAnalysis.ts`의 `OCR_MIN_CHARS`). F로 분류한 행도 `price_gold`는 채웁니다(보통 `null`).

### 품목(`item_category`)

화면 유형(A~F)과 별개로, **주 상품이 무엇인지**를 하나 고릅니다. 실제 사용자는 생활용품·가구를 많이 담으므로 품목별 정확도를 따로 봅니다(2026-11-04 결정).

| 품목 | 넣는 것(예) |
|---|---|
| `생활용품` | 주방용품·식기, 욕실·청소·세탁용품, 수납·정리, 생활 잡화, 반려동물 용품 |
| `가구·인테리어` | 가구, 조명, 침구·커튼·러그 등 패브릭, 인테리어 소품·액자, 식물·화분 |
| `패션` | 의류, 신발, 가방, 모자, 액세서리·주얼리·시계 |
| `뷰티` | 스킨케어, 메이크업, 향수, 헤어·바디 케어 제품 |
| `전자` | 가전(소형 가전 포함), 디지털 기기, 디지털 액세서리(케이스·충전기 등) |
| `기타` | 식품, 도서·문구, 취미·레저, 위에 없는 것 |

- **경계 기준**: 전원이나 배터리로 동작하는 기기는 `전자`입니다(헤어드라이어·가습기 포함). 단, 조명은 `가구·인테리어`입니다.
- 주 상품이 없거나(C 유형 SNS 게시물, D 유형 목록 화면) 판별할 수 없으면 **화면이 다루는 품목**을 고르고, 그것도 모르면 `기타`로 둡니다.
- 품목별 장수 할당은 없습니다. 실제로 담는 비율대로 섞습니다.

## 3. 가격 정답(`price_gold`) 규칙

현재 제품 정책을 따릅니다.

1. 화면의 **주 상품** 가격만 봅니다. 추천·목록·다른 상품 가격은 제외합니다.
2. 정가와 할인가가 같이 있으면 **정가**(할인 전, 보통 더 높거나 취소선이 있는 값)를 고릅니다.
3. 가격이 하나만 있으면 그 값을 씁니다.
4. **원화 금액만** 인정합니다. 외화만 있으면, 원화 가격이 없으면, 주 상품을 판별할 수 없으면 `null`입니다.
5. 쿠폰 금액, 배송비, 적립금, 좋아요·리뷰·조회·구매 수, 사이즈, 날짜는 가격이 아닙니다.

### 애매한 경우의 처리 예

아래 예의 숫자·상품은 모두 **가상**입니다.

| 화면에 보이는 것 | `price_gold` | `price_list` | `price_sale` | 근거 |
|---|---|---|---|---|
| ~~59,000원~~ 20% 47,200원 | `59000` | `59000` | `47200` | 규칙 2(정가 우선) |
| 할인율 없이 `39,000원` 하나 + "3만원 쿠폰팩", "무료배송" | `39000` | | `39000` | 규칙 3·5(쿠폰 금액은 가격 아님). 할인 상품이라고 표시돼 있지 않으면 `price_sale` 대신 `price_list`에 적어도 됩니다 — 보조 칸이라 지표에 영향 없음 |
| 판매가 45,000원 · 최대혜택가 38,000원(쿠폰 적용) | `45000` | `45000` | `38000` | 규칙 2. 쿠폰 적용가는 할인가로 보고 정가를 고릅니다 |
| `30% 26,900` (원 표기 없음, 할인율 옆 숫자) | `26900` | | `26900` | 할인율 옆 상품 가격은 원 표기가 없어도 가격 |
| SNS 게시물: 좋아요 2,348 · 댓글 120, 가격 언급 없음 | `null` | | | 규칙 5(C) |
| SNS 게시물 본문에 "정가 32,000원이에요"(소개 상품의 원화 가격) | `32000` | `32000` | | 주 상품의 원화 금액이면 SNS여도 가격. `type`은 C 그대로 |
| 상세 화면이지만 주 상품 가격은 화면 밖, 아래 추천 상품 가격만 보임 | `null` | | | 규칙 1·4(D) |
| 여러 상품이 나란히 있는 목록·피드 화면, 어느 것이 주 상품인지 모름 | `null` | | | 규칙 4(D) |
| `$17.51`만 표시 | `null` | | | 규칙 4(E). 환산하거나 소수점을 지운 `1751`이 정답이 아님 |
| 품절·판매 종료 표시 + 가격 `25,000원` | `25000` | | | 가격이 보이면 품절이어도 가격 |
| OCR 원문엔 `42.7OO`처럼 깨져 있지만 화면엔 `42,700원` | `42700` | | | 정답은 화면 기준(0절). OCR 실패는 'OCR 포함' 지표로 분리 |

### 잠정 처리 — 라벨링 시작 전에 확인

규칙만으로 답이 하나로 정해지지 않는 사례입니다. 아래 잠정안대로 라벨하고 `note`에 사유를 적습니다. 라벨러가 다르게 정하면 **라벨링을 시작하기 전에** 이 표를 고칩니다(측정 중에는 고치지 않음).

| 사례 | 잠정안 | 이유 |
|---|---|---|
| 가격 범위(`39,000원 ~ 49,000원`), 옵션별 가격만 보임 | `null` | 주 상품의 가격 하나를 판별할 수 없음(규칙 4). 틀린 값보다 빈칸 |
| 묶음·세트 가격과 단품 가격이 함께 보임 | 화면 제목이 가리키는 상품의 가격, 판별 불가면 `null` | 규칙 1·4 |
| 해외 몰에서 외화 + 원화 환산(`약 23,000원`)이 함께 보임 | `null`, `type` E | 환산 표시는 판매가가 아님. 원화 판매가가 따로 있으면 그 값 |
| 정기구독가·회원가만 할인가처럼 표시 | 일반 판매가(정가) | 규칙 2 |

## 4. 제품명(`name_keywords`)·브랜드(`brand_aliases`)

- **제품명**: 핵심어 1~2개를 `|`로 구분합니다(예: `브라탑|bra top`). 정답인 제품명에만 들어갈 만한 말을 고릅니다. 수량·용량·옵션(`1EA`, `470g`)은 넣지 않습니다.
- **브랜드**: 한·영 별칭을 `|`로 구분합니다(예: `이솝|Aesop`, `나이키|Nike`). 쇼핑몰 이름이 브랜드 자리에 나오는 화면이면 몰 이름도 별칭에 넣습니다.

### 실행기가 판정하는 방식

- 비교 전 양쪽을 **정규화**합니다: 유니코드 NFC → 소문자 → 문자·숫자만 남김(공백·기호 제거). 앱의 중복 판정 정규화(`src/lib/normalize.ts`)와 같은 규칙입니다.
- 제품명: 정규화한 핵심어 **하나라도** 모델의 `productName`에 들어 있으면 정답(부분 일치).
- 브랜드: 정규화한 별칭 **하나라도** 모델의 `brand`와 같으면 정답(완전 일치).
- 가격: 정수 그대로 비교합니다. `price_gold`가 `null`이면 모델도 `null`이어야 정답입니다.

## 5. 수집 규칙(Step 2)

- 30~40장. **실제 쓰임대로 품목을 섞습니다**(생활용품·가구/인테리어·패션·뷰티·기타). A·B·C·D 각 7~10장, E 3~5장(최소판 — 지시서 맨 위 상자). F는 생략하되 생기면 'OCR 부족'만 셉니다.
- 이미 캡처한 패션·뷰티 화면은 그대로 씁니다(2026-11-04 결정 — 화면 유형·장수는 그대로).
- 실제 쓰임과 같은 맥락에서 **본인이 직접 캡처**합니다. 같은 상품을 두 번 넣지 않습니다.
- 운영 앱(내부 계정)의 임시 폴더 `goldset`에 **AI가 채운 값을 고치지 않고** 저장합니다. 저장해야 `analysis_logs`에 `raw_text`가 남습니다.
- 수집이 끝나면 목록을 **고정**합니다(파일 목록 + 행 수). 측정을 시작한 뒤에는 정답셋을 고치거나 추가하지 않습니다.
