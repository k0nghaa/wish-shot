# 정답셋 라벨 규칙 (LABELING)

가격 자동채움 정확도를 재기 위한 **정답(라벨) 규칙**입니다. 측정을 시작한 뒤에는 이 규칙과 라벨을 고치지 않습니다. 고쳐야 할 일이 생기면 다음 버전 세트로 따로 만듭니다.

- 실행기: `samples/goldset-eval.ts` — 이 문서의 열 정의대로 `labels.csv`를 읽고 판정합니다.
- 원문 파일(`goldset/data/`)과 측정 결과(`goldset/out/`)는 **git에 올리지 않습니다**(`.gitignore`). OCR 원문에 타인의 계정명·댓글이 섞일 수 있고 레포가 공개돼 있기 때문입니다. 원문은 채팅·이슈·커밋 메시지에도 옮기지 않습니다.

## 0. 라벨링 전에

- **모델 출력을 보지 않고 라벨을 붙입니다.** `goldset/data/prod_parsed.csv`(운영 함수 출력)는 라벨이 끝날 때까지 열지 않습니다. 앱의 `goldset` 폴더 상세 화면에도 AI가 채운 값이 보이므로 열지 않습니다.
- 정답은 **화면에 실제로 보이는 값**입니다. OCR이 숫자를 잘못 읽었어도 정답은 화면의 값입니다. OCR 단계 실패는 실행기가 따로 셉니다('OCR 포함' 지표).
- `raw.csv`만으로 판단이 안 되면 본인이 찍은 캡처 원본(사진 앱)을 봅니다. `raw.csv`의 행 순서는 앱에 담은 순서(`created_at` 오름차순)와 같습니다.
- 대상은 **본인 계정으로 담은 기록만**입니다(`ops.internal_users`).

## 1. 파일과 열

`goldset/data/raw.csv` — 라벨링 입력(Step 3에서 만듦)

| 열 | 내용 |
|---|---|
| `id` | `analysis_logs.id` |
| `raw_text` | OCR 원문. 앱이 Edge Function에 보낸 텍스트와 같습니다(자르기·정규화 없음). 고치지 않습니다 |

`goldset/data/labels.csv` — 라벨러가 채우는 파일. 첫 줄은 아래 헤더를 그대로 씁니다.

```
id,type,item_category,price_gold,price_list,price_sale,price_foreign,name_keywords,name_gold,brand_aliases,holdout,note
```

| 열 | 필수 | 형식 | 설명 |
|---|---|---|---|
| `id` | ✔ | `raw.csv`의 id | 모든 행에 라벨이 하나씩 있어야 합니다(빠짐·중복 금지) |
| `type` | ✔ | `A`~`G` | 화면 유형(2절). 여러 개에 해당하면 우선순위가 높은 쪽 |
| `item_category` | ✔ | `생활용품` / `가구·인테리어` / `패션` / `뷰티` / `전자` / `기타` | 주 상품의 품목(2절 '품목'). 판정에는 쓰지 않고 결과를 품목별로 나눠 보는 데만 씁니다. 가운뎃점·슬래시·공백 차이는 같은 값으로 받습니다(`가구/인테리어`도 됨) |
| `price_gold` | ✔ | 정수(원) 또는 `null` | **정답 가격.** 숫자만 씁니다(`42700` — 콤마·`원`·공백 없음). 정답이 없으면 글자 그대로 `null`. **빈칸은 '아직 라벨 안 함'으로 보고 실행기가 거부합니다** |
| `price_list` | | 정수 또는 빈칸 | 정가(할인 전 가격)가 화면에 있으면 그 값. 없으면 빈칸 |
| `price_sale` | | 정수 또는 빈칸 | 할인가가 화면에 있으면 그 값. 없으면 빈칸 |
| `price_foreign` | | `통화코드 숫자` 또는 빈칸 | 외화 가격이 화면에 있으면 ISO 통화 코드와 숫자(`JPY 3980`, `USD 17.51`). 자릿수 구분 기호는 빼고, 소수점이 있으면 `.`으로 적습니다(유럽식 `1.299,90 €` → `EUR 1299.90`). 주 상품의 가격을 3절 규칙대로 고른 값(정가·할인가가 있으면 정가)입니다. **E는 반드시 채웁니다.** 채점에는 쓰지 않습니다 — 외화 처리를 바꿀 때 같은 정답셋으로 다시 재기 위한 기록입니다(2026-11-05 결정) |
| `name_keywords` | | `핵심어` 또는 `표기\|표기` | 이 화면 안에서 주 상품을 가려내는 제품명 핵심어 하나(여러 단어로 된 구도 됨). `\|`는 이은 말이 각각 주 상품을 가려낼 수 있을 때만 씁니다. 주 상품 없이 나란한 화면은 상품마다 잇습니다(4절). 빈칸이면 그 행은 제품명 지표에서 빠집니다 |
| `name_gold` | | 자유 또는 빈칸 | 앱의 제품명 칸에 들어가길 원하는 이름(4절). **채점에는 쓰지 않습니다** — 제품명을 다룰 때 같은 정답셋으로 다시 재기 위한 기록이라, 모델 출력을 보기 전인 지금 적습니다(2026-11-06 결정) |
| `brand_aliases` | | `별칭\|별칭` | 정답으로 인정할 브랜드 표기(예: `이솝\|Aesop`). 화면에 보이는 표기와 널리 알려진 공식 표기만 적고, 한·영을 둘 다 적을 필요는 없습니다(4절). 빈칸이면 브랜드 지표에서 빠집니다 |
| `holdout` | | `1` / `0` / 빈칸 | 홀드아웃 여부. **라벨러가 채우지 않습니다** — 라벨이 끝나면 시드 고정 스크립트(`goldset-holdout.ts`)가 유형마다 25%(반올림)를 지정합니다 |
| `note` | | 자유 | 애매한 행의 사유. 원문을 옮겨 적지 않습니다 |

- 셀에 콤마나 줄바꿈이 들어가면 큰따옴표로 감쌉니다(엑셀·구글 시트에서 CSV로 저장하면 자동 처리).
- **UTF-8로 저장합니다.** 엑셀은 기본 'CSV'로 저장하면 한글이 CP949로 저장돼 깨집니다. 반드시 **'CSV UTF-8(쉼표로 분리)'** 을 고릅니다(구글 시트 내려받기는 UTF-8). 깨진 글자가 있으면 실행기가 멈추고 알려 줍니다.
- `raw.csv`는 내보낸 그대로 둡니다. 원문에 CR(`\r`)이 섞여 있으면 실행기가 멈춥니다. 앱 원문엔 CR이 없으므로, 내보내기에서 생긴 것인지 확인한 뒤 `--crlf-to-lf`로 실행합니다.
- `price_list`·`price_sale`는 정가 우선 정책 자체를 나중에 다시 판단하기 위한 보조 칸입니다. `price_foreign`도 다음 개선을 위한 기록입니다. 측정 지표는 `price_gold`로만 계산합니다.
- G(중고거래)는 정가 우선을 적용하지 않으므로 `price_list`·`price_sale`을 비웁니다. 본문에 적힌 정가·구매가는 `note`에 "본문 정가 있음"처럼 사유만 적습니다.

## 2. 화면 유형(type)

| 유형 | 내용 | 정답 예 |
|---|---|---|
| A | 정가·할인가 병기(주로 커머스 상세) | 정가 |
| B | 가격 하나 + **가격이 아닌 숫자** — 가격이 하나만 보이는 커머스 화면(할인 없음, 할인율+할인가만, 할인가가 화면 밖)의 쿠폰·적립·배송비·리뷰 수, 가격이 한 줄 적힌 SNS 게시물의 좋아요·공유 수 | 그 가격 |
| C | SNS 게시물 — 좋아요·조회·댓글 수만, **가격 없음** | `null` |
| D | **여러 상품의 가격**이 섞임 — 상세 + 추천·광고, 큰 상품 카드 + 아래 목록, 같은 크기로 나란한 목록 | 주 상품 가격 또는 `null` |
| E | 외화 가격만(해외 몰) | `null`(`price_foreign`에 외화 기록) |
| F | 텍스트가 거의 없는 이미지 중심 화면 | `null`('OCR 부족' 판정만 기록) |
| G | 중고거래 상세(당근·번개장터 등) | **판매자가 등록한 가격** |

- **여러 유형에 해당하면 F > E > C > G > D > A > B 순으로 하나만** 고릅니다(측정이 더 까다로운 특징을 우선). 중고거래 매물은 다른 매물 가격이 섞여 있어도 G입니다.
- **B와 D의 경계**: 섞인 숫자로 가릅니다. 가격이 아닌 숫자(쿠폰 금액·배송비·적립금·좋아요 수)면 B, 다른 상품의 진짜 가격이면 D입니다. B는 '이 숫자가 가격인가', D는 '이 가격이 어느 상품의 것인가'를 재는 유형이라 틀렸을 때 고칠 프롬프트 규칙이 다릅니다. 둘 다 있으면 D입니다.
- **D의 정답은 두 갈래입니다.** 주 상품이 분명하면(상세 화면, 크게 위에 놓인 카드) 그 가격입니다. 주 상품을 정할 수 없거나(같은 크기로 나란한 상품) 주 상품 가격이 화면 밖이면 `null`입니다. `note`에 '주 상품 분명' / '나란히, 주 상품 불명' / '주 상품 가격 화면 밖'처럼 패턴을 적어 결과를 나눠 봅니다.
- **A·B·C는 주 상품의 원화 가격 수로 가릅니다.** SNS 게시물이면 가격이 없을 때 C, 하나일 때 B, 정가·할인가가 함께 보일 때 A입니다. 커머스 화면도 가격이 하나만 보이면(할인율+할인가만, 할인가가 화면 밖) B입니다(2026-11-05 변경 — 처음엔 '할인가만 보이는 커머스 화면은 없다'고 봤으나 수집 중 있는 것으로 확인).
- **G의 정답은 판매자가 매물에 등록한 가격**입니다. 사진 속 가격(가격표·영수증·옛 매물 캡처), 본문에 적은 구매가·정가, 아래 다른 매물 가격은 정답이 아닙니다. 커머스용 정가 우선 규칙(3절 규칙 2)을 적용하지 않습니다(2026-11-05 결정).
- 실행기는 앱과 같은 기준으로 **원문이 20자 미만인 행은 호출하지 않고 'OCR 부족'으로만 셉니다**(`useAnalysis.ts`의 `OCR_MIN_CHARS`). F로 분류한 행도 `price_gold`는 채웁니다(보통 `null`).

### 품목(`item_category`)

화면 유형(A~G)과 별개로, **주 상품이 무엇인지**를 하나 고릅니다. 실제 사용자는 생활용품·가구를 많이 담으므로 품목별 정확도를 따로 봅니다(2026-11-04 결정).

| 품목 | 넣는 것(예) |
|---|---|
| `생활용품` | 주방용품·식기, 욕실·청소·세탁용품, 수납·정리, 생활 잡화, 반려동물 용품 |
| `가구·인테리어` | 가구, 조명, 침구·커튼·러그 등 패브릭, 인테리어 소품·액자, 식물·화분 |
| `패션` | 의류, 신발, 가방, 모자, 액세서리·주얼리·시계 |
| `뷰티` | 스킨케어, 메이크업, 향수, 헤어·바디 케어 제품 |
| `전자` | 가전(소형 가전 포함), 디지털 기기, 디지털 액세서리(케이스·충전기 등) |
| `기타` | 식품, 도서·문구, 취미·레저, 위에 없는 것 |

- **경계 기준**: 전원이나 배터리로 동작하는 기기는 `전자`입니다(헤어드라이어·가습기 포함). 단, 조명은 `가구·인테리어`입니다.
- 주 상품이 없거나(C 유형 SNS 게시물, D 유형 목록 화면) 판별할 수 없으면 **화면이 다루는 품목**을 고르고, 그것도 모르면 `기타`로 둡니다.
- 품목별 장수 할당은 없습니다. 실제로 담는 비율대로 섞습니다.

## 3. 가격 정답(`price_gold`) 규칙

현재 제품 정책을 따릅니다.

1. 화면의 **주 상품** 가격만 봅니다. 추천·목록·다른 상품 가격은 제외합니다.
2. 정가와 할인가가 같이 있으면 **정가**(할인 전, 보통 더 높거나 취소선이 있는 값)를 고릅니다.
3. 가격이 하나만 있으면 그 값을 씁니다.
4. **원화 금액만** 인정합니다. 외화만 있으면, 원화 가격이 없으면, 주 상품을 판별할 수 없으면 `null`입니다.
5. 쿠폰 금액, 배송비, 적립금, 좋아요·리뷰·조회·구매 수, 사이즈, 날짜는 가격이 아닙니다.
6. **중고거래 상세(G)는 판매자가 등록한 가격**이 정답입니다. 규칙 2(정가 우선)를 적용하지 않습니다. 사진 속 가격, 본문의 구매가·정가, 다른 매물 가격은 가격이 아닙니다.

### 애매한 경우의 처리 예

아래 예의 숫자·상품은 모두 **가상**입니다.

| 화면에 보이는 것 | `price_gold` | `price_list` | `price_sale` | 근거 |
|---|---|---|---|---|
| ~~59,000원~~ 20% 47,200원 | `59000` | `59000` | `47200` | 규칙 2(정가 우선) |
| 할인율 없이 `39,000원` 하나 + "3만원 쿠폰팩", "무료배송" | `39000` | | `39000` | 규칙 3·5(쿠폰 금액은 가격 아님). 할인 상품이라고 표시돼 있지 않으면 `price_sale` 대신 `price_list`에 적어도 됩니다 — 보조 칸이라 지표에 영향 없음 |
| 판매가 45,000원 · 최대혜택가 38,000원(쿠폰 적용) | `45000` | `45000` | `38000` | 규칙 2. 쿠폰 적용가는 할인가로 보고 정가를 고릅니다 |
| `30% 26,900` (원 표기 없음, 할인율 옆 숫자) | `26900` | | `26900` | 할인율 옆 상품 가격은 원 표기가 없어도 가격 |
| `40% 52,000원`만 보이고 정가는 화면에 없음 | `52000` | | `52000` | 규칙 3(B). 할인율로 정가를 거꾸로 계산하지 않음 |
| 할인 상품인데 할인가가 아래 버튼에 가려 취소선 `36,000원`만 보임 + 리뷰 `2,315개` | `36000` | `36000` | | 규칙 3·5(B). 정답은 화면 기준. 쉼표 붙은 리뷰 수는 가격 아님. `note`에 '할인가 화면 밖' |
| SNS 게시물: 좋아요 2,348 · 댓글 120, 가격 언급 없음 | `null` | | | 규칙 5(C) |
| SNS 게시물 본문에 "정가 32,000원이에요"(소개 상품의 원화 가격) | `32000` | `32000` | | 주 상품의 원화 금액이면 SNS여도 가격. 가격이 있으므로 `type`은 B |
| 릴스 자막 `현재할인가 : 19,900원` + 좋아요 1,204 · 공유 2,310 | `19900` | | `19900` | 규칙 3·5(B). 쉼표 붙은 좋아요·공유 수는 가격 아님 |

## 4. 제품명(`name_keywords`·`name_gold`)·브랜드(`brand_aliases`)

- **제품명**: 모델이 **이 화면에서** 주 상품을 골랐는지 보는 핵심어를 하나 적습니다. 한 단어가 아니어도 되고 여러 단어로 된 구여도 됩니다(예: `와이드 셔츠`). 띄어쓰기·대소문자는 무시하지만, 모델 제품명에 그 순서대로 이어서 들어 있어야 정답입니다(아래 '실행기가 판정하는 방식').
  - 다른 상품과 구별되는지는 **이 화면 안에서만** 따집니다. 모델은 이 화면의 OCR 글자만 보므로, 틀린 답은 같은 화면의 다른 상품 이름·자막·계정명·안내 문구에서 나옵니다. 그런 글에 들어 있지 않은 말이면 됩니다. 다른 쇼핑몰의 상품이 같은 말을 많이 써도 상관없습니다.
  - 짧을수록 판정이 너그럽고, 길수록 엄격합니다. 이름에 꼭 있어야 한다고 보는 부분까지만 적습니다. 상품명 전체를 적으면 모델이 일부를 빼거나 순서를 바꾼 것도 오답이 됩니다. 원하는 이름 전체는 `name_gold`에 적습니다.
  - `|`는 "하나라도 들어 있으면 정답"이라는 뜻입니다. `|`로 이은 말이 **각각 그것만으로** 주 상품을 가려낼 수 있을 때만 씁니다(예: 같은 말의 다른 표기 `브라탑|bra top`). 흔한 말을 함께 이으면 그 말만 들어 있어도 정답이 되어 판정이 느슨해집니다. 주 상품 없이 나란한 화면은 아래 항목을 따릅니다.
  - 수량·용량·옵션(`1EA`, `470g`)과 브랜드명은 넣지 않습니다. 모델이 제품명에서 이들을 빼기 때문입니다. 브랜드인지 시리즈 이름인지 애매한 말, 색상처럼 옵션으로 지워질 수 있는 말도 피합니다. 그런 말이 빠지면 상품을 잘못 고른 것인지 이름만 다르게 쓴 것인지 구분할 수 없습니다. 핵심어는 맞는 상품을 골랐는지만 봅니다. 그런 말을 이름에 꼭 남기고 싶으면 `name_gold`에 적습니다.
- **원하는 제품명(`name_gold`)**: 앱의 제품명 칸에 들어가길 원하는 이름을 적습니다. 이번 측정에서는 채점하지 않습니다. 기준(똑같아야 하는지, 용량이 붙어도 되는지 등)은 제품명을 다루는 Phase에서 정합니다.
  - 기본은 지금 규칙대로 적습니다. 브랜드와 수량·용량·옵션은 빼고, 한글과 영문이 함께 있으면 한글로 적습니다.
  - 그 규칙과 다르게 원하면 원하는 대로 적고 `note`에 이유를 짧게 남깁니다. 나중에 규칙을 바꿀 근거가 됩니다.
  - 주 상품을 정할 수 없는 화면은 빈칸으로 둡니다.
- **브랜드**: 정답으로 인정할 표기를 `|`로 나열합니다. 모델이 낸 브랜드가 그중 **하나와** 같으면 정답이므로, 한·영을 둘 다 적어야 하는 칸이 아닙니다.
  - 화면에 보이는 표기는 모두 적습니다(로고·자막에 적힌 것 포함).
  - 영문은 화면에 적혀 있거나 널리 알려진 공식 표기일 때만 적습니다(예: `이솝|Aesop`, `나이키|Nike`). 모델은 이미지가 아니라 OCR 글자만 보므로, 원문에 없고 널리 알려지지도 않은 영문 이름은 낼 수 없습니다. 그런 이름을 찾아서 넣지 않습니다.
  - 쇼핑몰 이름이 브랜드 자리에 나오는 화면이면 몰 이름도 별칭에 넣습니다.
  - 브랜드로 볼지 애매하면 빈칸으로 둡니다. 그 행은 브랜드 지표에서만 빠집니다.
- **주 상품 없이 여러 상품이 나란한 화면**(가격이 `null`인 C·D — 같은 크기로 나란한 상품, 강조 없이 함께 소개된 상품): 화면에 있는 상품 중 **어느 것을 내도 정답**으로 봅니다(2026-11-06 결정).
  - `name_keywords`·`brand_aliases`에 상품마다 표기를 `|`로 잇습니다(예: `와이드 셔츠|세라믹 머그`, `가상브랜드|Gasang|다른가상브랜드`). 이은 말이 각각 화면의 진짜 상품 하나를 가리키므로 위 `|` 기준에 맞습니다. 본문 문구·태그·계정명을 제품명으로 넣는 실패는 그대로 오답으로 잡힙니다.
  - `name_gold`는 빈칸으로 두고, `note`에 `나란히, 주 상품 불명`을 적습니다.
  - 한계: 제품명과 브랜드를 따로 채점하므로, 한 상품의 이름과 다른 상품의 브랜드를 섞어 내도 둘 다 정답이 됩니다.
  - 이런 화면은 이후 이미지 영역 선택 작업(B4)에서, 사용자가 고른 상품에 맞춰 정보가 들어가도록 다시 다룹니다.

### 실행기가 판정하는 방식

- 비교 전 양쪽을 **정규화**합니다: 유니코드 NFC → 소문자 → 문자·숫자만 남김(공백·기호 제거). 앱의 중복 판정 정규화(`src/lib/normalize.ts`)와 같은 규칙입니다.
- 제품명: 정규화한 핵심어 **하나라도** 모델의 `productName`에 들어 있으면 정답(부분 일치).
- 브랜드: 정규화한 별칭 **하나라도** 모델의 `brand`와 같으면 정답(완전 일치).
- 가격: 정수 그대로 비교합니다. `price_gold`가 `null`이면 모델도 `null`이어야 정답입니다.

## 5. 수집 규칙(Step 2)

- 34~50장. **실제 쓰임대로 품목을 섞습니다**(생활용품·가구/인테리어·패션·뷰티·기타). A·B·C·D 각 7~10장, E·G 각 3~5장(최소판 — 지시서 맨 위 상자). F는 생략하되 생기면 'OCR 부족'만 셉니다.
  - **정답셋 v1은 A·B·C·D·G 8장씩, E 4장, F 0장, 모두 44장입니다**(2026-11-05 사람 결정 — 유형 간 분모를 같게).
  - B: 가격이 하나만 보이는 커머스 화면(쿠폰·적립·배송비·리뷰 수가 함께 보이는 화면)과 가격이 한 줄 적힌 SNS 게시물을 섞습니다.
  - D: 정답이 숫자인 화면(주 상품이 분명함)과 `null`인 화면(나란한 상품, 주 상품 가격이 화면 밖)을 섞습니다. 상세와 추천이 한 화면에 함께 담기는 경우는 드물어, 큰 상품 카드 + 목록이나 나란한 목록 화면으로도 채웁니다.
  - E: 1~2장은 엔화로 표시되는 **일본어** 사이트로 담습니다. 앱 OCR은 한국어·영어만 인식하므로, 빈칸 원인이 OCR인지 가격 규칙인지 나눠 보기 위해서입니다.
  - G: 사진 속에 가격이 보이는 매물(가격표·영수증·옛 매물 캡처), 본문에 정가·구매가를 적은 매물, 평범한 매물을 섞습니다.
- 이미 캡처한 패션·뷰티 화면은 그대로 씁니다(2026-11-04 결정).
- 실제 쓰임과 같은 맥락에서 **본인이 직접 캡처**합니다. 피드백으로 받은 화면처럼 다른 사람이 찍은 캡처는 쓰지 않고, 같은 패턴의 화면을 직접 찾아 캡처합니다. 같은 상품을 두 번 넣지 않습니다.
- 운영 앱(내부 계정)의 임시 폴더 `goldset`에 **AI가 채운 값을 고치지 않고** 저장합니다. 저장해야 `analysis_logs`에 `raw_text`가 남습니다.
  - 장수를 맞추려고 덜어낼 캡처는 **앱에 담기 전에** 고릅니다. 담으면 폼에 AI 값이 보여 고르는 기준이 흔들립니다. 패턴이 섞이도록 먼저 고르고 나머지는 캡처 순서대로 채웁니다.
  - 유형별로 몰아서 담습니다. `raw.csv`는 담은 순서대로 나오므로 행과 캡처를 맞추기 쉽습니다.
  - 제품명이 비어 저장이 막히면 아무 이름이나 입력해도 됩니다. 로그에는 폼 값과 상관없이 AI 원본과 원문이 남습니다.
  - 저장 뒤 '앨범에서 삭제'를 물으면 남겨 둡니다(라벨링 때 원본 캡처를 봄). 덮어쓰기 창이 뜨면 취소하고 같은 유형의 다른 캡처로 바꿉니다.
- 수집이 끝나면 목록을 **고정**합니다(파일 목록 + 행 수). 측정을 시작한 뒤에는 정답셋을 고치거나 추가하지 않습니다.
